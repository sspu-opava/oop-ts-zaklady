# **OOP v TypeScriptu – Lekce 7: Dědičnost a polymorfismus**

V předchozích šesti lekcích jsme postupně vytvořili interaktivní simulátor pohybujících se bublin. Naučili jsme se vytvářet instance třídy, pracovat s jejich vlastnostmi a metodami, ukládat objekty do pole a používat metody `forEach()`, `filter()`, `sort()` a `reduce()`.

Nyní naši aplikaci zásadně rozšíříme. Vedle kruhových bublin přidáme **čtverce a trojúhelníky**. Všechny objekty se budou pohybovat, odrážet od stěn a reagovat na uživatelské události.

Nové třídy však nebudeme vytvářet kopírováním celého původního kódu. Využijeme dva důležité principy OOP:

- **Dědičnost (inheritance):** Více tříd může sdílet vlastnosti a metody společného předka.
- **Polymorfismus (polymorphism):** Různé objekty mohou reagovat na stejné volání metody odlišným způsobem.

## **1. Proč potřebujeme dědičnost?**

Představme si, že chceme vedle kruhu vytvořit také čtverec a trojúhelník.

Všechny tři objekty budou mít řadu společných vlastností:

| Vlastnost            | Kruh         | Čtverec        | Trojúhelník         |
| -------------------- | ------------ | -------------- | ------------------- |
| Souřadnice `x`, `y`  | Ano          | Ano            | Ano                 |
| Velikost             | Ano          | Ano            | Ano                 |
| Barva                | Ano          | Ano            | Ano                 |
| Rychlosti `vx`, `vy` | Ano          | Ano            | Ano                 |
| Pohyb a odrazy       | Stejné       | Stejné         | Stejné              |
| Vykreslení           | Kruh         | Čtverec        | Trojúhelník         |
| Výpočet plochy       | Plocha kruhu | Plocha čtverce | Plocha trojúhelníku |

Vytvořit tři zcela samostatné třídy by samozřejmě šlo. Znamenalo by to však opakovat prakticky totožný konstruktor a metodu `pohyb()`.

Pokud bychom později chtěli například změnit pravidla odrazu, museli bychom stejnou úpravu provést ve třech třídách.

Dědičnost nám umožní společné části programu definovat pouze jednou.

## **2. Návrh nové hierarchie tříd**

`abstract class GrafickyObjekt`

Společné vlastnosti, konstruktor, pohyb a odrazy

Předpis metod `vykresli()`, `plocha()`, `obsahuje()`

`Kruh`

`p.circle()`

`Ctverec`

`p.square()`

`Trojuhelnik`

`p.triangle()`

Všechny tři třídy dědí společné vlastnosti a chování, ale každá má vlastní implementaci vykreslování, výpočtu plochy a testování bodu.

Společného předka pojmenujeme `GrafickyObjekt`.

Jeho potomky budou třídy `Kruh`, `Ctverec` a `Trojuhelnik`.

Původní třída `Bublina` se tedy změní na specializovanou třídu `Kruh`, která bude využívat sdílené vlastnosti a metody svého předka.

## **3. První krok: Společná rodičovská třída**

Nejprve si prohlédněme samotný základ nové hierarchie.

```
abstract class GrafickyObjekt {

  constructor(
    public x: number,
    public y: number,
    public velikost: number,
    protected barva: string,
    private vx: number,
    private vy: number
  ) {}

  // Společná metoda všech grafických objektů.
  pohyb(p: p5): void {
    this.x += this.vx;
    this.y += this.vy;

    const r = this.velikost / 2;

    if (this.x < r || this.x > p.width - r) {
      this.vx *= -1;
      this.x = p.constrain(this.x, r, p.width - r);
    }

    if (this.y < r || this.y > VYSKA_SCENY - r) {
      this.vy *= -1;
      this.y = p.constrain(this.y, r, VYSKA_SCENY - r);
    }
  }

  // Metody, které musí definovat potomci.
  abstract vykresli(p: p5): void;
  abstract plocha(): number;
  abstract obsahuje(x: number, y: number): boolean;
}
```

Tento kód obsahuje několik nových konstrukcí, které si postupně vysvětlíme.

### **A. Co znamená&#x20;**`abstract class`**?**

Klíčové slovo `abstract` označuje abstraktní třídu.

Taková třída představuje společný základ pro další třídy, ale nemůžeme přímo vytvářet její instance.

Následující zápis proto TypeScript odmítne:

```
const objekt = new GrafickyObjekt(...); // Chyba
```

Naopak konkrétního potomka vytvořit můžeme:

```
const objekt = new Kruh(100, 150, 40, "red", 2, 1);
```

Abstraktní třída je vhodná tehdy, když chceme definovat společné chování několika druhů objektů, ale samotný obecný objekt nemá v naší aplikaci dostatečně konkrétní význam.

### **B. Co znamená&#x20;**`protected`**?**

V předchozí lekci jsme poznali `public` a `private`. Nyní přidáme třetí přístupový modifikátor.

| Modifikátor | Přístup v rámci třídy | Přístup v potomkovi | Přístup zvenčí |
| ----------- | --------------------- | ------------------- | -------------- |
| `public`    | Ano                   | Ano                 | Ano            |
| `protected` | Ano                   | Ano                 | Ne             |
| `private`   | Ano                   | Ne                  | Ne             |

V našem konstruktoru:

```
protected barva: string
```

znamená, že vlastnost `barva` mohou používat metody třídy `GrafickyObjekt` i metody jejích potomků.

Proč je to užitečné?

Třída `Kruh` bude potřebovat znát svou barvu při vykreslování:

```
p.fill(this.barva);
```

Pokud bychom `barva` deklarovali jako `private`, potomci by k ní neměli přímý přístup.

Naproti tomu rychlosti `vx` a `vy` můžeme ponechat jako `private`, protože samotnou aktualizaci pohybu kompletně zajišťuje rodičovská třída.

### **C. Co je abstraktní metoda?**

Všimněte si těchto deklarací:

```
abstract vykresli(p: p5): void;
abstract plocha(): number;
abstract obsahuje(x: number, y: number): boolean;
```

Abstraktní metoda obsahuje pouze svůj předpis, nikoli vlastní tělo.

Například:

```
abstract vykresli(p: p5): void;
```

říká, že každý konkrétní potomek musí poskytovat metodu `vykresli()` se stanovenými parametry a návratovým typem.

Neříká však, *jak* se má vykreslení provést.

To totiž závisí na konkrétním geometrickém tvaru.

## **4. Druhý krok: Dědičnost pomocí&#x20;**`extends`

Vytvoříme třídu `Kruh`, která bude dědit od `GrafickyObjekt`.

```
class Kruh extends GrafickyObjekt {

  override vykresli(p: p5): void {
    p.noStroke();
    p.fill(this.barva);
    p.circle(this.x, this.y, this.velikost);
  }

  override plocha(): number {
    const r = this.velikost / 2;
    return Math.PI * r ** 2;
  }

  override obsahuje(x: number, y: number): boolean {
    return Math.hypot(this.x - x, this.y - y)
      <= this.velikost / 2;
  }
}
```

Nové klíčové slovo je:

```
extends GrafickyObjekt
```

Znamená, že třída `Kruh` je potomkem třídy `GrafickyObjekt`.

Automaticky tak získává její společné vlastnosti a metody.

Nemusíme proto znovu definovat konstruktor ani metodu `pohyb()`.

### **Co znamená&#x20;**`override`**?**

Klíčové slovo `override` označuje metodu, která přepisuje metodu zděděnou od rodičovské třídy.

V našem případě jde o konkrétní implementaci abstraktní metody.

Když napíšeme:

```
kruh.vykresli(p);
```

vyvolá se implementace definovaná v třídě `Kruh`.

Pokud bychom omylem použili nesprávný název metody za `override`, TypeScript nás upozorní, že takovou metodu v předkovi nelze přepisovat.

## **5. Třetí krok: Další potomci**

Podobně vytvoříme třídu `Ctverec`.

```
class Ctverec extends GrafickyObjekt {

  override vykresli(p: p5): void {
    p.noStroke();
    p.fill(this.barva);

    const s = this.velikost;

    // Čtverec vykreslíme kolem jeho středu.
    p.square(this.x - s / 2, this.y - s / 2, s);
  }

  override plocha(): number {
    return this.velikost ** 2;
  }

  override obsahuje(x: number, y: number): boolean {
    const r = this.velikost / 2;

    return (
      Math.abs(x - this.x) <= r &&
      Math.abs(y - this.y) <= r
    );
  }
}
```

A třídu `Trojuhelnik`:

```
class Trojuhelnik extends GrafickyObjekt {

  override vykresli(p: p5): void {
    p.noStroke();
    p.fill(this.barva);

    const s = this.velikost;

    // Rovnoramenný trojúhelník.
    p.triangle(
      this.x,       this.y - s / 2,
      this.x - s/2, this.y + s / 2,
      this.x + s/2, this.y + s / 2
    );
  }

  override plocha(): number {
    return this.velikost ** 2 / 2;
  }

  override obsahuje(x: number, y: number): boolean {
    const s = this.velikost;

    // Souřadnice bodu vzhledem ke středu tvaru.
    const dx = Math.abs(x - this.x);
    const dy = y - this.y;

    // Test bodu uvnitř našeho rovnoramenného
    // trojúhelníku se základnou i výškou s.
    return (
      dy >= -s / 2 &&
      dy <= s / 2 &&
      dx <= (dy + s / 2) / 2
    );
  }
}
```

Všechny tři třídy mají společného předka, ale poskytují vlastní implementaci stejných metod.

Například metoda `plocha()` používá pro každý geometrický tvar jiný matematický vzorec:

| Třída         | Vzorec               |
| ------------- | -------------------- |
| `Kruh`        | \\(S=\pi r^2\\)      |
| `Ctverec`     | \\(S=a^2\\)          |
| `Trojuhelnik` | \\(S=\frac{ah}{2}\\) |

U trojúhelníku jsme zvolili základnu i výšku rovnou vlastnosti `velikost`, takže lze vzorec zjednodušit na `velikost ** 2 / 2`.

Tím také vidíme, že vlastnost `velikost` nemusí znamenat totéž jako původní `prumer`. V naší nové hierarchii představuje šířku a výšku vymezujícího prostoru tvaru.

# **6. Kompletní aplikace sedmé lekce**

Nyní spojíme nové třídy s dosavadním simulátorem.

Zachováme animaci, přidávání objektů myší, mazání, řazení a výpočet součtu ploch. Nově bude možné volit druh objektu pomocí kláves `1`, `2` a `3`.

Nejdůležitější změnou bude **jediné pole typu&#x20;**`GrafickyObjekt[]`**, které může obsahovat instance všech tří potomků**.

Soubor `src/main.ts`:

```

import p5 from "p5";

// ==============================================
// 1. KONSTANTY A DATOVÉ TYPY
// ==============================================

const SIRKA = 600;
const VYSKA_SCENY = 320;
const VYSKA_PANELU = 60;

const POCET_OBJEKTU = 18;

// Union type určuje povolené druhy tvarů.
type DruhTvaru = "kruh" | "ctverec" | "trojuhelnik";


// ==============================================
// 2. ABSTRAKTNÍ RODIČOVSKÁ TŘÍDA
// ==============================================

abstract class GrafickyObjekt {

  // Společné vlastnosti všech grafických objektů.
  constructor(
    public x: number,
    public y: number,
    public velikost: number,
    protected barva: string,
    private vx: number,
    private vy: number
  ) {}

  // Společná implementace pohybu.
  // Potomci tuto metodu automaticky dědí.
  pohyb(p: p5): void {

    // Změna souřadnic podle rychlosti.
    this.x += this.vx;
    this.y += this.vy;

    // Polovina velikosti vymezuje hranice objektu.
    const r = this.velikost / 2;

    // Odraz od levé nebo pravé hranice.
    if (this.x < r || this.x > p.width - r) {
      this.vx *= -1;
      this.x = p.constrain(this.x, r, p.width - r);
    }

    // Odraz od horní nebo dolní hranice scény.
    if (this.y < r || this.y > VYSKA_SCENY - r) {
      this.vy *= -1;
      this.y = p.constrain(this.y, r, VYSKA_SCENY - r);
    }
  }

  // Společná metoda pro změnu barvy.
  zmenBarvu(novaBarva: string): void {
    if (novaBarva.trim() !== "") {
      this.barva = novaBarva;
    }
  }

  // Abstraktní metody nemají tělo.
  // Každý konkrétní potomek je musí implementovat.
  abstract vykresli(p: p5): void;
  abstract plocha(): number;
  abstract obsahuje(x: number, y: number): boolean;
}


// ==============================================
// 3. POTOMEK: KRUH
// ==============================================

class Kruh extends GrafickyObjekt {

  // Přepisujeme metodu vykreslení.
  override vykresli(p: p5): void {
    p.noStroke();
    p.fill(this.barva);

    // U kruhu je velikost jeho průměrem.
    p.circle(this.x, this.y, this.velikost);
  }

  // Vzorec pro plochu kruhu.
  override plocha(): number {
    const r = this.velikost / 2;
    return Math.PI * r ** 2;
  }

  // Bod leží uvnitř kruhu, pokud jeho vzdálenost
  // od středu nepřesahuje poloměr.
  override obsahuje(x: number, y: number): boolean {
    const vzdalenost = Math.hypot(
      this.x - x,
      this.y - y
    );

    return vzdalenost <= this.velikost / 2;
  }
}


// ==============================================
// 4. POTOMEK: ČTVEREC
// ==============================================

class Ctverec extends GrafickyObjekt {

  override vykresli(p: p5): void {
    p.noStroke();
    p.fill(this.barva);

    const s = this.velikost;

    // square() standardně používá levý horní roh.
    // Proto odečteme polovinu strany.
    p.square(
      this.x - s / 2,
      this.y - s / 2,
      s
    );
  }

  // Plocha čtverce: strana na druhou.
  override plocha(): number {
    return this.velikost ** 2;
  }

  // Bod musí ležet uvnitř vodorovných
  // i svislých hranic čtverce.
  override obsahuje(x: number, y: number): boolean {
    const r = this.velikost / 2;

    return (
      Math.abs(x - this.x) <= r &&
      Math.abs(y - this.y) <= r
    );
  }
}


// ==============================================
// 5. POTOMEK: TROJÚHELNÍK
// ==============================================

class Trojuhelnik extends GrafickyObjekt {

  override vykresli(p: p5): void {
    p.noStroke();
    p.fill(this.barva);

    const s = this.velikost;

    // Rovnoramenný trojúhelník:
    // jeden vrchol nahoře, dva dole.
    p.triangle(
      this.x,       this.y - s / 2,
      this.x - s/2, this.y + s / 2,
      this.x + s/2, this.y + s / 2
    );
  }

  // Plocha trojúhelníku:
  // (základna * výška) / 2.
  // Obě hodnoty jsou zde rovny s.
  override plocha(): number {
    return this.velikost ** 2 / 2;
  }

  // Test bodu v našem rovnoramenném trojúhelníku.
  override obsahuje(x: number, y: number): boolean {
    const s = this.velikost;

    // Relativní souřadnice vůči středu.
    const dx = Math.abs(x - this.x);
    const dy = y - this.y;

    // Horní a dolní hranice trojúhelníku
    // a dvě šikmé strany.
    return (
      dy >= -s / 2 &&
      dy <= s / 2 &&
      dx <= (dy + s / 2) / 2
    );
  }
}


// ==============================================
// 6. HLAVNÍ APLIKACE p5.js
// ==============================================

const sketch = (p: p5) => {

  // Paleta barev.
  const barvy: string[] = [
    "#1cc5c9",
    "#fba24c",
    "#a38cf5",
    "#f779a0"
  ];

  // Pole možných druhů tvarů.
  const druhy: DruhTvaru[] = [
    "kruh",
    "ctverec",
    "trojuhelnik"
  ];

  // POLYMORFISMUS:
  // Jedno pole může obsahovat instance všech
  // tříd odvozených od GrafickyObjekt.
  let objekty: GrafickyObjekt[] = [];

  // Druh objektu přidávaného kliknutím.
  let vybranyDruh: DruhTvaru = "kruh";


  // --------------------------------------------
  // VYTVOŘENÍ JEDNOHO OBJEKTU
  // --------------------------------------------

  function vytvorObjekt(
    x: number,
    y: number,
    druh: DruhTvaru
  ): GrafickyObjekt {

    const velikost = p.random(20, 70);
    const r = velikost / 2;

    // Zajistíme, aby celý tvar vznikl ve scéně.
    const px = p.constrain(x, r, SIRKA - r);
    const py = p.constrain(y, r, VYSKA_SCENY - r);

    const barva = p.random(barvy);
    const vx = p.random(-2.5, 2.5);
    const vy = p.random(-2.5, 2.5);

    // Podle druhu vytvoříme konkrétního potomka.
    switch (druh) {

      case "kruh":
        return new Kruh(
          px, py, velikost, barva, vx, vy
        );

      case "ctverec":
        return new Ctverec(
          px, py, velikost, barva, vx, vy
        );

      case "trojuhelnik":
        return new Trojuhelnik(
          px, py, velikost, barva, vx, vy
        );
    }
  }


  // --------------------------------------------
  // OBNOVENÍ SCÉNY
  // --------------------------------------------

  function obnov(): void {
    const okraj = 35;

    // Array.from() opakovaně vytváří nové instance.
    // Jejich konkrétní třída se vybírá náhodně.
    objekty = Array.from(
      { length: POCET_OBJEKTU },
      () => {
        const x = p.random(okraj, SIRKA - okraj);
        const y = p.random(
          okraj,
          VYSKA_SCENY - okraj
        );

        return vytvorObjekt(
          x, y, p.random(druhy)
        );
      }
    );
  }


  // --------------------------------------------
  // JE MYŠ UVNITŘ SCÉNY?
  // --------------------------------------------

  function mysVeScene(): boolean {
    return (
      p.mouseX >= 0 &&
      p.mouseX < SIRKA &&
      p.mouseY >= 0 &&
      p.mouseY < VYSKA_SCENY
    );
  }


  // --------------------------------------------
  // INICIALIZACE
  // --------------------------------------------

  p.setup = () => {
    p.createCanvas(
      SIRKA,
      VYSKA_SCENY + VYSKA_PANELU
    );

    obnov();
  };


  // --------------------------------------------
  // ANIMAČNÍ SMYČKA
  // --------------------------------------------

  p.draw = () => {

    p.background("#f0f0f0");

    // Všechny objekty zpracováváme stejně.
    // Konkrétní typ objektu zde neřešíme!
    objekty.forEach((objekt) => {
      objekt.pohyb(p);
      objekt.vykresli(p);
    });

    // Každý objekt vypočítá svou vlastní plochu.
    const soucetPloch = objekty.reduce(
      (soucet, objekt) => soucet + objekt.plocha(),
      0
    );

    // Spodní informační panel.
    p.noStroke();
    p.fill("#dce4ec");
    p.rect(0, VYSKA_SCENY, SIRKA, VYSKA_PANELU);

    p.fill("#243347");
    p.textSize(13);

    p.text(
      `Objektů: ${objekty.length} | ` +
      `Plocha: ${Math.round(soucetPloch)} px² | ` +
      `Nový: ${vybranyDruh}`,
      12, VYSKA_SCENY + 22
    );

    p.text(
      "1/2/3 = druh | Klik = přidat | D = smazat | " +
      "S = seřadit | R = obnovit",
      12, VYSKA_SCENY + 45
    );
  };


  // --------------------------------------------
  // KLIKNUTÍ MYŠÍ
  // --------------------------------------------

  p.mousePressed = () => {

    if (!mysVeScene()) return;

    // push() přidá konkrétní instanci potomka.
    objekty.push(
      vytvorObjekt(
        p.mouseX,
        p.mouseY,
        vybranyDruh
      )
    );
  };


  // --------------------------------------------
  // OVLÁDÁNÍ KLÁVESNICÍ
  // --------------------------------------------

  p.keyPressed = () => {

    switch (p.key.toLowerCase()) {

      case "1":
        vybranyDruh = "kruh";
        break;

      case "2":
        vybranyDruh = "ctverec";
        break;

      case "3":
        vybranyDruh = "trojuhelnik";
        break;

      case "d":
        // Každý tvar má vlastní metodu obsahuje().
        if (mysVeScene()) {
          objekty = objekty.filter(
            (objekt) =>
              !objekt.obsahuje(p.mouseX, p.mouseY)
          );
        }
        break;

      case "s":
        // Seřazení podle společné vlastnosti.
        objekty.sort(
          (a, b) => a.velikost - b.velikost
        );
        break;

      case "r":
        obnov();
        break;
    }
  };
};


// ==============================================
// SPUŠTĚNÍ APLIKACE
// ==============================================

new p5(sketch);

```

Aplikace má stejný základ jako v šesté lekci. Místo jednoho druhu objektu však nyní pracuje se třemi třídami, které sdílejí společného předka.

## **7. Nejdůležitější princip: Polymorfismus**

Podívejme se na deklaraci pole:

```
let objekty: GrafickyObjekt[] = [];
```

V předchozí lekci jsme používali pole:

```
let bubliny: Bublina[] = [];
```

Tehdy všechny prvky představovaly instance jedné konkrétní třídy.

Nyní je situace odlišná.

Do pole `GrafickyObjekt[]` můžeme vložit instance všech konkrétních potomků:

```
const objekty: GrafickyObjekt[] = [
  new Kruh(100, 100, 40, "red", 2, 1),
  new Ctverec(200, 100, 50, "blue", -1, 2),
  new Trojuhelnik(300, 100, 60, "green", 1, -2)
];
```

TypeScript toto přiřazení akceptuje, protože každá z uvedených tříd dědí od `GrafickyObjekt`.

A nyní přichází podstata polymorfismu:

```
objekty.forEach((objekt) => {
  objekt.pohyb(p);
  objekt.vykresli(p);
});
```

**Voláme stejné metody, ale skutečné chování závisí na konkrétním typu instance.**

V případě `pohyb()` se používá společná zděděná implementace.

V případě `vykresli()` se naopak automaticky vybere implementace odpovídající skutečnému typu objektu:

- Instance `Kruh` vykreslí kruh.
- Instance `Ctverec` vykreslí čtverec.
- Instance `Trojuhelnik` vykreslí trojúhelník.

Nemusíme proto psát:

```
if (objekt instanceof Kruh) {
  // ...
} else if (objekt instanceof Ctverec) {
  // ...
}
```

Program nemusí konkrétní typ zjišťovat. Zavolá společné rozhraní a správná metoda se vybere automaticky.

Právě tento mechanismus označujeme jako **polymorfismus**, konkrétně polymorfismus podtypů s dynamickým výběrem implementace metody.

## **8. Polymorfismus není pouze vykreslování**

Stejný princip využíváme při výpočtu plochy:

```
const soucetPloch = objekty.reduce(
  (soucet, objekt) => soucet + objekt.plocha(),
  0
);
```

Představme si, že pole obsahuje kruh, čtverec a trojúhelník se stejnou hodnotou `velikost = 40`.

**Stejná metoda, rozdílné výsledky**

Kruh

1256.6 px²

Čtverec

1600.0 px²

Trojúhelník

800.0 px²

Společná velikost

40 px

Součet ploch

3656.6 px²

Výpočty odpovídají metodám `plocha()` v uvedených třídách. Tvary v ilustraci jsou schematicky zmenšené.

Stejná metoda `plocha()` vrací pro každý geometrický tvar jinou hodnotu.

Funkce `reduce()` přitom nemusí znát žádný z použitých matematických vzorců.

Až bychom například přidali novou třídu `Elipsa`, stačilo by v ní implementovat správnou metodu `plocha()`. Výpočet součtu v hlavním programu by zůstal beze změny.

To je praktický přínos polymorfismu: **nové typy objektů lze zapojit do již existujících algoritmů, pokud dodržují společné rozhraní.**

## **9. Kdy potřebujeme&#x20;**`super()`**?**

Možná jste si všimli, že potomci `Kruh`, `Ctverec` a `Trojuhelnik` neobsahují vlastní konstruktor.

Je to záměrné. Pokud potomek nedefinuje svůj konstruktor, využije zděděný konstruktor rodičovské třídy.

Někdy však chceme, aby měl potomek vlastní inicializační logiku.

V takovém případě potřebujeme klíčové slovo `super`.

Například do třídy `Kruh` bychom mohli doplnit:

```
constructor(
  x: number,
  y: number,
  velikost: number,
  barva: string,
  vx: number,
  vy: number
) {
  super(x, y, velikost, barva, vx, vy);
}
```

Tento konstruktor zavolá prostřednictvím `super()` konstruktor rodičovské třídy `GrafickyObjekt`.

Ten inicializuje všechny společné vlastnosti.

V odvozeném konstruktoru musíme zavolat `super()` před použitím `this`.

V naší současné aplikaci by takový konstruktor pouze opakoval to, co TypeScript a JavaScript zvládnou automaticky. Proto jej do kompletního příkladu zatím nepřidáváme.

V příštích lekcích se však `super()` stane důležitým, pokud budou mít jednotlivé druhy objektů další vlastní vlastnosti.

## **10. Jak funguje metoda&#x20;**`obsahuje()`**&#x20;u různých tvarů?**

Ve čtvrté lekci jsme vytvořili metodu `obsahuje()`, která zjišťovala, zda bod leží uvnitř kruhové bubliny.

Nyní máme tři různé geometrické tvary.

Každý vyžaduje vlastní způsob testování bodu:

| Tvar        | Princip testování                        |
| ----------- | ---------------------------------------- |
| Kruh        | Vzdálenost od středu nepřesahuje poloměr |
| Čtverec     | Bod leží v rozsahu obou souřadnic        |
| Trojúhelník | Bod leží mezi třemi stranami             |

To je další přirozené použití polymorfismu.

Hlavní program při mazání objektů volá:

```
objekty = objekty.filter(
  (objekt) => !objekt.obsahuje(p.mouseX, p.mouseY)
);
```

Přitom vůbec neřeší, zda právě testujeme kruh, čtverec nebo trojúhelník.

O správný geometrický výpočet se postará konkrétní instance.

Pro začátečníky může být matematika testování bodu uvnitř trojúhelníku náročnější. Při prvním probírání dědičnosti ji není nutné detailně odvozovat. Stačí pochopit, že všechny objekty poskytují stejnou metodu, přestože její implementace je rozdílná.

## **12. Samostatné úkoly pro studenty**

**Úkol 1 – Rozpoznávání dědičnosti**

Určete, které vlastnosti a metody jsou definovány v rodičovské třídě a které v jednotlivých potomcích. Vysvětlete, proč třída `Kruh` nepotřebuje vlastní metodu `pohyb()`.

**Úkol 2 – Změna způsobu vykreslení**

Upravte třídu `Ctverec` tak, aby byl každý čtverec vykreslen s černým obrysem. Ostatní geometrické objekty musí zůstat beze změny.

**Úkol 3 – Vlastní konstruktor**

Doplňte třídě `Kruh` explicitní konstruktor, který prostřednictvím `super()` zavolá konstruktor rodičovské třídy. Ověřte, že aplikace funguje stejně jako před úpravou.

**Úkol 4 – Nový potomek**

Vytvořte třídu `Elipsa`, která bude dědit od `GrafickyObjekt`. Doplňte metody `vykresli()`, `plocha()` a `obsahuje()`. Pro začátek může mít elipsa pevný poměr hlavních poloos 2 : 1.

**Úkol 5 – Změna rychlosti podle typu**

Upravte aplikaci tak, aby se kruhy pohybovaly pomaleji než trojúhelníky. Nejprve zkuste problém vyřešit pouze vhodným nastavením parametrů konstruktoru při vytváření objektů.

**Úkol 6 – Vlastní polymorfní metoda**

Doplňte do rodičovské třídy abstraktní metodu `popis(): string`. Každý potomek musí vracet jiný text s názvem geometrického tvaru. Pomocí `forEach()` vypište všechny popisy do konzole.

## **14. Shrnutí sedmé lekce**

V této lekci jsme se poprvé odklonili od jediné konkrétní třídy a vytvořili **hierarchii spolupracujících tříd**.

Seznámili jsme se s následujícími konstrukcemi:

| Konstrukce          | Význam                                    |
| ------------------- | ----------------------------------------- |
| `extends`           | Definování dědičnosti                     |
| `abstract class`    | Abstraktní rodičovská třída               |
| `abstract` u metody | Povinnost potomka poskytnout implementaci |
| `protected`         | Zpřístupnění vlastností také potomkům     |
| `override`          | Explicitní přepsání zděděné metody        |
| `super()`           | Volání konstruktoru rodičovské třídy      |
| `GrafickyObjekt[]`  | Polymorfní pole různých potomků           |

Z pedagogického hlediska je nejdůležitější pochopit, že dědičnost a polymorfismus nejsou totéž.

**Dědičnost** umožňuje sdílet a rozšiřovat společné vlastnosti a chování.

**Polymorfismus** umožňuje s objekty různých konkrétních tříd pracovat prostřednictvím společného typu a volat na nich stejné metody, jejichž skutečná implementace se může lišit.

### **Co doporučuji pro osmou fázi?**

Na tomto základě bych navázal **odlišným chováním jednotlivých potomků**, nejen odlišným vykreslováním.

Mohli bychom vytvořit tři druhy pohybujících se objektů:

- Kruh by se pohyboval po sinusové trajektorii.
- Čtverec by sledoval obdélníkovou vlnu.
- Trojúhelník by se pohyboval po pilové vlně.

Každý typ by přepsal metodu zodpovědnou za výpočet trajektorie. Společná rodičovská třída by však nadále organizovala posun v čase a vykreslování.

Tím bychom polymorfismus ukázali ještě výrazněji: různé objekty by se nejen jinak zobrazovaly, ale také **odlišně chovaly**, přestože hlavní animační smyčka by se nemusela měnit.
